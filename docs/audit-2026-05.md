# Prow stabilisation audit — 2026-05-12

Pre-feature-work review of the connector framework, run after Passes A,
B, C1, C2, C3, and D had merged and before the project moves into
application-tier work (KEV connector, persister, API, UI).

The audit was diagnostic; only the changes explicitly flagged as
"fix in place" below were applied.

---

## Executive summary

The framework is mostly in good shape. Static checks are clean
(`ruff`, `ruff format`, `mypy`, `lint-imports`). Module boundaries are
enforced by eleven import-linter contracts and all eleven hold.
Dependencies have no project-level vulnerabilities. The slow,
subprocess-driven test suite is fast and stable: 26 tests in ~21 s
real time, 5/5 clean runs back-to-back, no leaked processes.

The audit surfaced one clear correctness bug and one significant
test-infrastructure problem the maintainer should be aware of before
adding more code:

1. `test_runtime_negotiation_times_out_when_connector_never_responds`
   was racing its own teardown and failed deterministically on Linux.
   Fixed in place.
2. Thirteen "fast" connector tests share a teardown pattern
   (`asyncio.start_server` + `await server.wait_closed()` without
   closing the server-side writer in the connection handler) that
   hangs indefinitely on Python 3.12.3 (Linux/WSL2) and on Python
   3.12.10 (Windows). It is not flaky — it is consistent. These tests
   must be either skipped on those platforms or refactored before any
   wall-clock-bounded CI matrix that uses a current Python patch
   release.

Documentation has drifted in roughly a dozen places since the design
notes were frozen, but every drift is "design says A, code does the
sensible thing B" — not silent under-specification. The README status
section was the most-read drifter; fixed in place.

`prow connector test` was emitting a fake issue ID; replaced with an
honest roadmap reference. `prow connector validate` and `prow connector
dev --no-watch` both exit 0 against `tests/connector/dev_fixtures/good_pkg`
in under a second.

**Recommendation:** proceed to feature work *after* the maintainer
either confirms the thirteen hanging tests pass on the machine they
verified the suite on, or adopts one of the mitigations in Action
Item 1. Everything else is nice-to-have.

### Honest assessment

Only one test individually exceeds the 1-second-per-test threshold by
more than the subprocess-spawn floor:
`test_slow_then_ok_does_not_restart` at 6.38 s. It is correctly slow
by construction — it asserts that a single ~6 s health probe is
tolerated without restart by waiting through it on a real subprocess
(see the `PROW_CONNECTOR_TEST_HEALTH_MODE=slow_then_ok` branch in
`transport_stdio.py:_reply_health_probe`). Reducing the 6.0 s sleep
would defeat what the test is asserting.

The watcher tests at ~2 s each are bounded by the `PollingObserver`'s
~1 s diff-snapshot cadence, which is documented in the test comments
and is genuinely the floor for the API being tested.

Subprocess-spawn tests cluster around 0.3 s, the realistic CPython
import + fork cost on this kernel. Lowering further is not free.

The remaining fast tests are all sub-100 ms or sub-10 ms.

**Finding:** the slow suite is honest about being slow. No
unjustified sleeps surface in the durations table.

**5/5 clean.** Total wall-clock 1 m 44 s. Variance ~400 ms across
five runs. The slow suite is rock-solid.

### Non-slow suite — two pre-existing issues

A. `tests/connector/protocol/test_negotiation.py::test_runtime_negotiation_times_out_when_connector_never_responds`
   **fails deterministically** on Linux:

```
>   assert isinstance(runtime_result, NegotiationTimeoutError)
E   AssertionError: assert False
E    +  where False = isinstance(ProtocolError(
                         'Stream closed before hello negotiation completed.'),
                         NegotiationTimeoutError)
```

   The `silent_connector` helper read 1 byte from the runtime's
   `hello` line, then closed the connection. The runtime's 10 ms
   timeout was supposed to fire first, but the closed-stream EOF
   reached the runtime's `read_one_envelope` before the timer did,
   so `StreamClosedBeforeLineError` was raised and propagated as a
   generic `ProtocolError`, not as `NegotiationTimeoutError`. The
   intent of the test (assert the *timeout* path) was never
   reliably exercised.

   **Fixed in place.** `silent_connector` now `await asyncio.sleep(1.0)`
   without ever reading or closing, so the timeout is the only path
   to a result. Test now passes (1.00 s wall-clock for that one
   timeout).

B. Thirteen tests hang indefinitely at `await server.wait_closed()`
   on Python 3.12.3 (WSL2 Linux) and on Python 3.12.10 (Windows):

   - `tests/connector/test_runner.py::test_runner_main_hello_emit_shutdown`
   - `tests/connector/test_transport_stdio.py::*` (all 7)
   - `tests/connector/test_runtime_transport.py::*` (all 5)

   The common pattern: each test opens an `asyncio.start_server` on
   `127.0.0.1:0` whose connection handler holds a `StreamWriter` but
   never closes it (the handler is a `runtime_peer` or `peer`
   function that returns when its `read_messages` loop exits on
   EOF). After the test body closes its client writer, the server
   handler's reader does see EOF and the handler does return — that
   half works. But `Server.wait_closed()` then never resolves
   because, on these Python patch releases, an unclosed
   server-side `StreamWriter` keeps `Server._waiters` armed.

   A direct (no pytest) repro confirms the same hang on Python
   3.12.3 ext4 WSL2:

   ```
   peer started t=0.002s
   peer rt.start() done t=0.002s
   client about to emit t=0.002s
   client got ack t=0.002s
   client closing writer t=0.002s
   client writer closed t=0.002s
   server.close() called t=0.002s
   peer awaiting wait_dispatch_finished t=0.303s
   peer done t=0.303s
   < hangs forever in await server.wait_closed() >
   ```

   This is **not flaky.** It is consistent, 100 % reproducible on
   the two interpreters available to the audit. The maintainer's
   claim of a clean local run is presumably from either a slightly
   older 3.12 patch release where the `Server.wait_closed()`
   semantics differed, or from a CI run on a different combination.
   It would be very unsafe to assume the next contributor's
   machine matches.

   **Not fixed in place.** The fix is a structural change to ~13
   tests (add `writer.close(); await writer.wait_closed()` to every
   `runtime_peer` / `peer` and likely wrap `await server.wait_closed()`
   in `asyncio.wait_for(..., timeout=2.0)` with a suppressed
   `TimeoutError`) which is bigger than the audit's "fix in place"
   remit. Tracked as Action Item 1.

### Fix in place — area 3

`tests/connector/protocol/test_negotiation.py`: rewrote
`silent_connector` to never close the stream. (1 file changed,

## 6. CI workflow audit

`.github/workflows/ci.yml`:

| Step | In CI | In local "before commit" instructions |
| --- | --- | --- |
| `ruff check .` | yes | yes |
| `ruff format --check .` | yes | yes |

| `lint-imports --config importlinter.ini` | yes | yes |

Local and CI run the same five-step gate. There is no slow-test
opt-out — `pytest -q` runs everything, so the slow suite *does* run
in CI.

### Findings

- **Python matrix.** `pyproject.toml` declares `requires-python = ">=3.12"`.
  CI matrix is `python-version: ["3.12"]`, which `actions/setup-python`
  resolves to whatever the latest 3.12.x is on the runner image. Recent
  3.12.x releases satisfy ">=3.12", so this works today; pinning to a
  specific patch (or testing both the minimum supported 3.12 and the
  latest) would make the build more reproducible.
- **Caching.** `cache: pip` is set on `actions/setup-python`, which is
  the canonical lightweight pip cache. `pip install -e ".[dev]"` is
  re-run on every push but cached wheels make it cheap. This is fine.
- **Branch protection.** Not visible from the repo; the maintainer
  must verify required status checks include the `quality` job. The
  audit cannot configure branch protection.
- **Slow test coverage.** The slow suite is included in the same
  `pytest -q` run as the fast suite. CI is not cheating on coverage.
- **Concurrency.** The workflow does not set `concurrency:`. Two
  pushes in quick succession run two jobs. Not a defect, but a
  ~free-cost saving to consider.

### Fix in place — area 6

Nothing required. The pipeline is correct. The Python-patch-pin and
concurrency-key suggestions are tracked as nice-to-have action items.

| `connector-supervisor-boundary` | Supervisor stack cannot reach `runner` / `transport_stdio` / `context`. | Useful. | Symmetric to above. |
| `stix-leaf` | `prow.stix` cannot reach any other `prow.*` package. | Useful. | Pre-positions `prow.stix` to ship as its own library if needed. |
| `bus-boundary` | `prow.bus` cannot reach `prow.db` / `prow.api`. | Useful. | The bus is meant to be implementation-substitutable; this is its contract surface. |
| `api-surface` | `prow.api` cannot import connector / enrich / stix / taxii / cli. | Useful. | The API is supposed to be a thin layer over interfaces, not call into modules directly. |
| `stix-adapter-isolation` | `stix2` upstream library reachable only from `prow.stix._stix2_adapter`. | Useful. | Implements ADR-0009 fork-readiness: the `ignore_imports` allow-list is intentionally one line and exists with comments explaining the trigger conditions for fork. |

No contract has `unmatched_ignore_imports_alerting` weakened — the
default ("error") is in effect on every contract that has an
`ignore_imports`. The `stix-adapter-isolation` contract is the only
one that uses `ignore_imports`, and its allow-list is one entry.

The connector framework's runtime / connector / protocol / transport
separation is enforced by seven of the eleven contracts; the
separation lines up with the runtime design note.

### Possible gaps (out of scope to fix)

- `prow.enrich` has no contract of its own. With no code in it yet,
  there is nothing meaningful to forbid, but a stub contract may be
  worth adding when enrichers are written so the "interface only"
  promise is enforceable.
- `prow.config` and `prow.telemetry` are similarly contract-free.
  Same reasoning: meaningless until those modules have code.

### Fix in place — area 7

Nothing required. The contracts are real, all hold, and the
amendment policy (no silent weakening) is in place.

## Action items

Severity legend:
**blocker** = must address before tagging v0.1;
**important** = best to address before adding more code on top;
**nice-to-have** = quality-of-life or hardening.

1. **Fix the thirteen tests that hang at `await server.wait_closed()`.**
   Severity: **blocker** for any environment where the suite must
   complete unattended (CI, fresh contributor laptop). Estimate:
   1–2 hours. The mechanical change is: every test-side
   `start_server` connection handler (`runtime_peer`, `peer`,
   `silent_connector`, etc.) needs a `try`/`finally` that closes its
   `writer` and awaits `writer.wait_closed()` before returning; the
   call-sites can also wrap `server.wait_closed()` in
   `asyncio.wait_for(..., timeout=2.0)` with a suppressed
   `TimeoutError` if there's any concern about leaked third-party
   sockets. The pattern already used by `_run_with_connector` in
   `tests/connector/protocol/test_negotiation.py` is the model.
